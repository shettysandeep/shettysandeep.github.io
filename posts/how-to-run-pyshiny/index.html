You have a Python Shiny app that runs great locally with the following command on the terminal:

shiny run --reload --launch-browser app.py

It fires up a browser and serves the app at localhost:8080 or some other port (the last four digits), and now you want to deploy it on the internet for general public consumption or feedback.

There are several ways one can achieve this. Shinyapp.io or Posit Cloud Connect seems like a natural choice as they are well suited for Shiny’s foundational design choices with “sticky” load balancing and such. Among other options are cloud platforms like Google Cloud, AWS or Azure. Given the variety of services that come bundled with a cloud service you may be tempted to deploy your app with one of them.

Google Cloud (GC) offers a few alternatives to deploy a Python shiny app: a containerized mode; connecting the project Github repo to GC; and thirdly uploading the app script and the data to the Google cloud. These options present different degrees of difficulties and suitability based on the complexity of the app. In this note, I show how to deploy the app to Google cloud (gc) using containers. This is a simple article to orient you with just that using Google Cloud.

Containerizing the Shiny app

Containerizing means putting your script (app.py) and all that it depends upon to run smoothly (libraries, dependencies, configuration, data) into a ‘container’.

Containers are like packages that are self-sufficient, isolated, and standardized for a particular use case. They are portable and run consistently across any environment.

To containerize your app you need:

  • Docker installed, which you can install by following the instructions here;

  • a `requirements.txt` doc, which is just a list of python packages you require to run your app (you can obtain it by executing pip freeze > requirements.txt from a terminal after activating the specific python virtual environment you used for the app;

  • a Dockerfile file (with no extension) that provides instructions on how to set up the image (a machine within your machine with the specs you need to run your app. It becomes self-contained and thus can be shared around or deployed to the cloud.)

To sandbox your experiments with Docker and containers, I recommend putting your app.py script, your dataset, and the above documents into a “test” folder. You can subsequently delete this once you have the app running smoothly.

When building the image, if you are on a Mac, you will need to build the image that is compatible with Linux platform. By default Docker builds the image leveraging your computer architecture. In the case of my M2 mac, the images created under arm64 architecture (of non-Intel macbooks) will not run on the GC. You will need an image that is linux/amd64 compatible one. The below command will help.

docker buildx build --platform linux/amd64 -t name_of_image

Before you move to the next step of dealing with GC, ensure that your container is running as expected - i.e. when you run the docker container it fires up a browser and serves your app at localhost:8080 or some other port.

An example of a Dockerfile for a Python Shiny app is as follows:

FROM python:3.11-slim


RUN apt-get update && \
    apt-get install -y --no-install-recommends build-essential && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Copy the requirements file and install dependencies first (for efficient Docker caching)
COPY requirements.txt .
RUN pip install --no-cache-dir --upgrade -r requirements.txt

# Copy the rest of the application code into the container
COPY . .

# Expose the port the app will run on
EXPOSE 8080

# Command to run the application using uvicorn when the container starts
CMD [ "shiny","run","app.py","--host","0.0.0.0","--port","8080"]

Setting up, signing and authenticating GC account

There are a couple of steps needed to access GC services:

  1. Sign up on GC (account creation, payment setup.)

  2. Install Google Cloud CLI.

    The GC command line interface (CLI) enables you to start/stop services, upload containers, folders to the cloud from the terminal. You can also do the same from the GC’s web console but I find the console a tad confusing with too much information and parameters to sift through. I prefer the terminal.

  3. Authenticate your GC account (quite straightforward) via terminal to use the GC CLI. Follow instructions here

Now you should have access to gcloud command on the terminal. This offers you plenty of flexibility and access to information in a streamlined way. See the gcloud cheatsheet.

GC operations from the terminal

After you create an account on GC you will be defaulted into a project that will have a Project ID with a human-readable name. The Project ID is a”globally” unique identifier for your project. You could continue working under this project. I’d recommend this for now to avoid being overwhelmed by the details in the documentation. But if you want to create a new one. See documentation

The project that was created for me was pro-gecko-482907-h1 and which is what I will use below in the commands. Please replace it with your own project ID. You can find your project ID on the GC console dashboard.

Create a repo under GC project.

You habe to create a repository under your project to host the container image. You can do this from the GC console or via terminal with the below command. In my case, I created a repo called test-repo under the project pro-gecko-482907-h1. The command below will create a repo with the same name for you. You can change the name of the repo as you like. The command below will create a repo with the same name for you. You can change the name of the repo as you like.

gcloud artifacts repositories create test-repo --repository-format=docker --location=europe-west1

Use the --location flag to specify the location that you want. It is not always obvious which location to choose and the nearest is not always the cheapest or best. The service that you are looking for should be available in the location you choose. This is most pertinent with Vertex and Gemini. But here I chose europe-west1. You can check the pricing and the locations here.

Make a copy of the local Docker image

Once you have built the local image, you need to make a copy of it with the name that is compatible with the GC registry. The below command will do that for you.

docker tag fpi_amd europe-west1-docker.pkg.dev/pro-gecko-482907-h1/test-repo/fpi-amd-test:latest

Push the app to the GC registry

After you have the image with the right name, you can push it to the GC registry with the below command.

docker push europe-west1-docker.pkg.dev/pro-gecko-482907-h1/test-repo/fpi-amd-test

Run the app on GC Run

Now that you have the image in the GC registry, you can deploy it to GC Run with the below command. This will make your app available on the internet. You can access it via the URL provided by GC after deployment.

gcloud run deploy fpi-amd-test --image europe-west1-docker.pkg.dev/pro-gecko-482907-h1/test-repo/fpi-amd-test --platform managed --region europe-west1 --allow-unauthenticated --max-instances 1

Hopefully, you should see the app running at the URL provided by GC after deployment. You can share this URL with others to access your app.

If you would like to stop the app, you can do so with the below command.

gcloud run services update fpi-amd-test --max-instances 0 --region europe-west1

You could achieve the same from the GC console where you can set the auto-scaling to zero to stop the service. This will not delete the entire service and will maintain all its revisions and configuration so if you want to simply restart it again, you can do so.

This will stop traffic and avoid costs while keeping the service configuration intact. You can restart it later by setting the max-instances back to 1 or more.

Conclusion

In this article, I showed how to deploy a Python Shiny app on Google Cloud using containers. This is just one way to deploy your app, and there are other options available depending on your needs and preferences. The key steps involved containerizing your app, setting up a GC account, and deploying the app to GC Run. With these steps, you can make your app accessible to anyone on the internet.
